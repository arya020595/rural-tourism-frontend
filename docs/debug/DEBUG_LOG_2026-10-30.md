## 1. Branch name casing (GitHub Desktop "cannot be resolved to branch")

The branch was first created as `features/newfeatures29oct` (lowercase). This
repo's branches use **`Features/`** with a capital F, and on Windows git stored
the new branch inside the existing `Features` folder while HEAD pointed at the
lowercase name, so pushing failed with *"features/newfeatures29oct cannot be
resolved to branch"*. HEAD was pointed at `refs/heads/Features/newfeatures29oct`;
nothing was lost. Keep the `Features/` prefix in this repo (the backend uses
lowercase `features/`).

## 4. New: Sebut Harga / Quotation module

Full reference: **`docs/QUOTATION_MODULE_FRONTEND.md`**. New pages

UX decisions made with the operator during the session (all in the code):

- No draft step — saving makes it **Sent**; no Mark-as-Sent prompt, no delete.
- Save shows a **Saving…** overlay and a **Quotation Created / Updated**
  pop-up (short, no extra text); OK opens the detail page.
- Form buttons: Cancel · Save Quotation (no "Save & View PDF").
- Prepared By is a free-text field; it pre-fills Operator Name on conversion.
- Notes & Terms: **Use Standard Text** / **Save Default** (company default).
- Pax labels and placeholder match the booking forms; nationality row full width.
- Detail: number + badge left, PDF Quotation / Booking / Receipt right; Cancel
  (red, left) and Edit (yellow, right) at the bottom; "Yes, cancel" above "No";
  no PDF button once cancelled; name/amount removed under the number; no
  convert hint text.
- List: Status filter on the column header (like Booking); created-date range;
  "Created Date" column; no filter chips, no icon legend.
- Edge "Saved info" autofill pop-up suppressed on the form (neutral names, trap
  fields).
- No separate quotation calendar (discussed; open quotations aren't bookings).

## 5. Booking forms: `prefill` input; shared mapper

- `activity-`, `accommodation-`, `package-booking-form`: new
  **`@Input() prefill`** used in **add** mode (edit / view still use
  `booking`). `applyBooking()` reads `this.mode === 'add' ? prefill : booking`.
  With a prefill the package form also loads each company's services.
- `mapBookingToDetail` + its time helper were duplicated in `booking-edit` and
  `booking-detail`; moved to **`utils/booking-detail.mapper.ts`** and used by
  both pages and by the quotation conversion. Output unchanged.

## 6. Conversion pages and back navigation

- `booking-add` / `ereceipt-add` read `?quotation=<id>`, load the draft
  (`utils/quotation-prefill.util.ts`), show a "From quotation QT_…" banner, lock
  the type (Add Booking) or redirect to the matching e-receipt type, and add
  `quotation_id` to the payload.
- **Kembali** on both pages returns to the quotation when opened from one
  (E-Receipt used to always go to `/e-receipt`).
- E-Receipt → receipt page passes `?from=quotation&date=<first day>`; the
  receipt pages (activity, accommodation, package) then show **Kembali Ke
  Tempahan** and open **Booking in calendar view** on that day
  (`booking-home` handles `?view=calendar&date=YYYY-MM-DD`). Normal receipts
  keep "Kembali Ke Transaksi" and go back as before.

## 7. Bug found by functional QA — inputs showed rubbish they didn't save

On the quotation form, phone / pax / price stripped bad characters from the
**saved** value, but the box could still **show** them (typing `3x` showed
"3x" while 3 was kept; `12.345abc` stayed visible). When the cleaned value
doesn't change Angular has nothing new to render. Fix: `cleanInput()` writes
the cleaned value back to the input element; the phone field uses one-way
`[ngModel]`. Re-tested: all pass.
