# Frontend Debug Log — 2026-10-04

Debugging session log for the Rural Tourism (RuTEC) Ionic + Angular frontend,
covering work from 2026-10-01 to 2026-10-04. See also `DEBUG_LOG_2026-09-30.md`
for the previous session. Future debugging sessions should be recorded in a
new `DEBUG_LOG_<date>.md` file in this `docs/debug/` folder rather than editing
this one.

> Stack: Ionic 8 + Angular 18 + Capacitor 7. Offline-first (IndexedDB + service
> worker). API base URL per environment in `src/environments/`.

---

## 1. Pop-up buttons pushed off-screen on short screens

**Symptom:** on small laptops and landscape tablets, the operator logo **Apply
Crop** button (Company Profile) was below the visible area, so the logo
couldn't be saved. My Transaction's "Select Date" modal had the same problem
on landscape phones.

**Root cause:** both had a width limit but no height limit. The crop modal's
height followed the image (a square logo at 620px wide ≈ 620px tall); the date
modal was a fixed 480px on any screen ≥768px wide — which includes landscape
phones (~390px tall).

**Fix pattern (reuse it for any new pop-up):**
- cap the pop-up at the viewport: `max-height: calc(100dvh - 24px)` (with a
  `100vh` fallback line before it);
- lay it out as a column and keep the buttons outside the scrolling area
  (`flex-shrink: 0`, or an `ion-footer` for `ion-modal`);
- let only the content (image/calendar) shrink or scroll.

For the crop modal the cropper library's own `max-height: 100%` never applied
(its wrapper has no fixed height), so the image is capped directly with
`::ng-deep img.ngx-ic-source-image { max-height: calc(100dvh - 190px) }`.
Files: `company-profile.page.scss`, `global.scss`.

**Test sizes used:** 1366×768, 1024×600, 1180×820, 390×844, 844×390.

## 2. Android's own date/time dialog cut off on a tablet

**Symptom:** on a tablet in landscape, the clock dialog for the booking form
Time field was cut off (Cancel half visible).

**Root cause:** `<input type="time">` / `type="date"` open a dialog drawn by
Android/the browser, not the app. No CSS or media query can resize it.

**Fix:** replaced them with pickers the app draws itself:
- **Time** (`activity-booking-form`): read-only field + centred `ion-modal`
  with an `ion-datetime` wheel, 12-hour with AM/PM, Cancel/Set only. Stored
  value stays `HH:mm` (24h); the field shows e.g. `07:20 PM`.
- **Date** — new shared component
  `booking-forms/components/booking-date-sheet/`: a centred calendar pop-up
  (month/year header with arrows, month grid, year grid). Used by every booking
  form date (Activity date, Accommodation check-in/out, Package date). Check-out
  gets a `min` so earlier days are greyed out.
- Dates with a non-cancelled booking for the operator's company show a dot,
  from the new backend endpoint `GET /api/bookings/booked-dates` (fetched per
  visible month, cached; if it fails the calendar still works without dots).

**Bug found while doing this:** `activity-booking-form` started with
`bookingDate = '12/03/2026'`. The native date input hid it (not a valid
`YYYY-MM-DD`), but it still passed the "date is required" check, so a booking
saved without picking a date was stored as **12 March 2026**. It now starts
empty.

**Gotcha — Ionic auto-height modal:** an `ion-modal` with `--height: auto`
only sizes to its content if `.ion-page` inside it is
`position: relative; display: block; contain: content;` (see
`ion-modal.date-sheet-modal` in `global.scss`).

## 3. Same calendar reused for Dashboard and My Transaction

- **Dashboard Trend** (`home.page.*`): the Ionic wheel popover was replaced by
  the shared calendar with `pickMode="month"` (emits `YYYY-MM`). "To" can't be
  before "From" and vice versa. Year range is now 2020 to 5 years ahead
  (`trendMinDate` / `trendMaxDate`); the backend has no year limit.
- **My Transaction** (`my-transaction.page.*`): single "Select Date" →
  **From / To range**, filtering on the device as before (each card's booking
  date), applied instantly. Booking dots are turned off here with
  `[showBookedDates]="false"`.

**Old quirk removed:** the single-date filter used *today* as its "no filter"
value, so picking today's date showed everything. "Nothing picked" now means
no filter.

## 4. Company profile: owner fields and the wrong email

**Symptom:** saving Company Profile as a second Operator Admin failed (see the
backend log §4).

**Root cause (frontend part):** the Email field was filled from the
*logged-in* user's own account (`data.email`), while Owner Name showed the
owner. A co-admin saving the form therefore sent their own email onto the
owner's account.

**Fix:** Email now shows the owner's email (`owner_email` from the API). Owner
Name and Email are read-only with "(Hanya pemilik boleh ubah / Owner only)" for
anyone who isn't the owner (`isCompanyOwner`, from `owner_user_id`), and are
not sent on save. The backend enforces the same rule.

## 5. Money fields: cents and 2 decimal places

**Symptom:** Total, Deposit and package item Price only accepted whole
numbers; saved amounts like `300.50` displayed as `300.5`.

**Root cause:** three layers blocked the decimal point — the `(input)`
handler stripped every non-digit, `(keydown)` blocked `.`, and
`type="tel" pattern="[0-9]*"` gave a phone keypad. The submit pages then
`Math.trunc`'d the deposit. When opening a saved booking, the form filled the
fields with `number.toString()`, which drops trailing zeros.

**Fix:**
- New `booking-forms/money-input.util.ts`: `sanitizeMoney()` (digits, one
  `.`, max 2 decimals), `blockNonMoneyKey()`, `formatMoney()` (→ `300.50`).
- The money inputs in all three booking forms use them
  (`inputmode="decimal"`, tidy to 2 decimals on blur). Phone/pax inputs are
  unchanged.
- `booking-add`, `booking-edit`, `ereceipt-add`: deposit rounded to 2
  decimals instead of truncated.
- Requires the backend migration that makes `total_deposit` DECIMAL.

**Dashboard:** the revenue card always shows 2 decimals
(`RM 40,574.50`); the revenue chart's y-axis and tooltip use 2 decimals via a
new `isCurrency` input on `dashboard-chart-panel`. Count charts stay whole.
