## 3. Registration: upload problems shown as a pop-up

**Background:** at the 2026-10-27 onboarding, registrations with documents
failed. The cause was the production server's nginx limiting requests to 1MB
(backend log §6), which is now fixed on the server. The app's own error
messages were also easy to miss: a 1.8-second toast without the file name or
size.

**Change** (`register/register.page.ts`): upload problems now open an
`ion-alert` that stays until the user taps OK.

| When | Pop-up |
|---|---|
| File over 5MB chosen | **File is too large**, with the file name, document, size (e.g. 8.4MB) and advice. The file is not attached. |
| Wrong file type chosen | **Unsupported file type**, with the file name; allows PDF / JPG / PNG |
| All files over 20MB (on submit) | **Uploads are too large**, with the combined size |
| Server returns 413 | **Upload too large** |
| Connection dropped mid-upload (status 0, or the backend's "Upload was interrupted") with files attached | **Upload was interrupted**, advising to check the connection; smaller files help on slow connections |

- `UPLOAD_FIELD_LABELS` maps each field to its document name for the message.
- `services/http-interceptor.service.ts`: skips its generic toast for a
  registration upload (`/auth/register` with a `FormData` body) that failed
  with status 0 or "Upload was interrupted", so only the pop-up shows. 413 was
  already skipped.
- Checked in the browser: a 6.3MB PDF and an 8.4MB JPG each show the pop-up,
  and no toast appears.

**Not done yet:**
- The pop-up text is English only. The form labels are bilingual.
- `company-profile.page.ts` uploads still use the old toast.

## 6. Dashboard receipt list: phone column, package names, Excel download

`home/home.page.{ts,html,scss}`,
`home/dashboard/components/receipt-list-table/*`,
`home/dashboard/dashboard.models.ts`.

**Phone No. column** after Booked By, from the booking's `phone_number`
(already in the API response). "-" when empty.

**Package rows showed "-" as the service name.** A package has no single
`product_name`. It now lists the products in `package_companies`, the same

at ~220px and wraps (font 16px, full name on hover). The same cap was applied

(`booking-home/components/booking-list-table.component.*`).

**Download Excel button** ("Muat Turun Excel / Download Excel") beside the
heading. It downloads **every** receipt in the current date range, not just
the visible page (loops `getBookings` at `per_page: 100`), plus received
package referrals. Built with **ExcelJS** (new dependency), loaded with
`import('exceljs')` only on click. Saved through `NativeDownloadService`
(browser download on the website, share sheet on Android; it now takes a
`dialogTitle`). File: `receipt-list_<from>_to_<to>.xlsx`.

- **Sheet "Receipts":** Receipt No. (`BA_` + id, or the legacy `PE…` number,
  as on the PDF), Tourist Name, Phone No., Service Name, Type, Created At (a
  real date in Malaysia time). Green header, frozen top row, filters, Service
  Name wraps.
- **Sheet "Customers":** one row per customer, **most visits first**, ties
  by latest visit. Columns: Tourist Name (latest), Names Used, Phone No.,
  Email, No. of Visits, Returning? (Yes = 2 or more visits, row shaded),
  First Visit, Last Visit, Services Booked.
  - Grouped by **phone** (digits only; `+60` / `60` → `0`), else **email**
    (case-insensitive). A receipt with neither is its own row. **Names are

  - **First / Last Visit** = the Booked Date (`activity_date`, else
    `check_in_date`), read as `YYYY-MM-DD` with no timezone conversion (same
    rule as `utils/activity-date.util.ts`). Falls back to the receipt date.

## 7. Booking forms: telephone number required

**Why:** without a phone number, returning customers cannot be recognised
(§6). Phone was optional, so most bookings had none.

**Change:** activity, accommodation and package booking forms
(`booking-forms/components/*-booking-form`):
- red `*` on "No. Telefon/Telephone No.";
- on submit: empty → *"Sila masukkan no. telefon / Telephone number is
  required."*; fewer than 8 digits → *"No. telefon tidak sah / Please enter a
  valid telephone number."* (8 allows foreign numbers such as Singapore);
- also applies when editing an old booking that has no phone.

Email stays optional. **Not enforced on the backend yet:** app 1.0.8 has no
phone check, and its offline-queued bookings would fail to sync if the server
rejected them. Add the backend rule once operators are on 1.0.9 or later.

## 16. Play Store: one user couldn't find RuTEC (Android 16, not Huawei)

Reported at the 2026-10-27 onboarding. Not an app problem: the release
bundle has no native `.so` libraries (so the 16 KB page-size rule doesn't
apply), minSdk 24, Internet permission only, no `uses-feature` and no ABI
filters. Likely device or account causes:
- the phone isn't **Play Protect certified** (Play Store → Settings → About);
- the Google account's **country** isn't Malaysia;
- a Family Link or work profile;
- search ranking.

Next step: have the user open
`https://play.google.com/store/apps/details?id=com.sabah.ruraltourism` and
send what it shows; look the model up in Play Console → Device catalog (and
check excluded devices). Workaround: use rutec.my in the browser.
