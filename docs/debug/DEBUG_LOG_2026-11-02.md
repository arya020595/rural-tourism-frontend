## 3. Why the spinner stayed up after a decision

**Symptom.** After Approve, the "Menyimpan / Saving..." spinner covered the
page for several seconds; the browser test's tab click hit the spinner.

**Cause.** The approve / reject request waited for the operator email, and
Gmail SMTP took ~4.4 s.

**Fix (backend).** The email is now sent in the background. The decision
returns at once, and the spinner closes after about a second.

## 8. Bug: quotation → booking showed "This booking has been cancelled"

**Symptom.** A deposit booking made from a quotation opened with "This
booking has been cancelled." and no Cancel / Update / Payment Receipt buttons.
Found while taking the guide screenshots.

**Cause.** Quotation conversion saves the booking as `booked`. The booking
detail page only treated `pending` as open, so `booked` fell through to the
"cancelled" message, and `editBooking()` ignored it. The booking list and edit
pages already treated `booked` like `pending`. The local DB had 5 such bookings.

**Fix** (`booking-detail/booking-detail.page.{ts,html}`):
- `canEdit()` is now true for `pending` **or** `booked`;
- the action buttons and `editBooking()` use it.

Checked in the browser: a `booked` booking shows the three buttons, and Update
opens `/booking-home/edit/:id`.

## 8b. Offline mode check (5 bugs fixed)

An end-to-end offline test ran on a production build (service worker on, local backend only), as a demo operator. It covered:

- logging in, then reopening the app offline;
- opening every page;
- creating, editing and making a walk-in e-receipt offline;
- reconnecting.

It ran in two modes: airplane mode, and connected-but-no-internet.

| Bug | Fix |
|---|---|
| Offline booking marked `permanently_failed` after 3 "no connection" tries, so it never synced | `sync.service.ts`: status 0 / 502 / 503 / 504 keep it `pending` without using a retry |
| "HTTP ERROR 503" reopening offline right after the first login | `sw.js` precaches `index.html` + all JS/CSS from `ngsw.json` at install; prunes old builds on activate |
| Pages never opened online (Add/Edit Booking) don't load offline | same `sw.js` precache |
| Offline edit: empty form, and saving failed on `/api/products/company/…` | `booking-edit.page.ts`: booking from `booking_cache`, products from the device cache |
| No-internet e-receipt showed a QR to a temporary id | receipt pages: a non-numeric id counts as "not synced yet" (pending notice) |

Add/Edit Booking also say "successfully" only if the change really reached the server.

Result: 25/32 checks passed before the fixes; **35/35 in both modes** after. Details are in `docs/OFFLINE_BOOKING_IMPLEMENTATION.md` → "Fixes from the end-to-end offline test (2026-11-02)".
